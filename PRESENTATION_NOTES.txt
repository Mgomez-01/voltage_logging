1. SYSTEM OVERVIEW
-------------------------------------------------------------------------------
The ESP8266 reads three analog signals through a CD74HC4067 multiplexer: a
voltage, the PID Temp Sensor (100k NTC, controls the heater) and the AUX Temp
Sensor (MF55 10k NTC at a second location, logged only as a redundancy /
sanity check). It logs them as CSV to a microSD card and regulates a 12 V
heater with a PID controller that drives an AOD4144 MOSFET using PWM. The board creates its own WiFi network. A web page (served from
internal flash) shows live data and has buttons to start/stop logging, manage
the SD log files, control the heater, tune the PID and reset after a fault.

Signal chain:
  Voltage source    --> MUX C0 --\
  PID Temp Sensor  --> MUX C1 ---+-- MUX COM --> ESP8266 A0 (10-bit ADC)
  AUX Temp Sensor  --> MUX C2 --/
  ESP8266 SPI (D5-D8) <------> microSD module      (data logs)
  ESP8266 GPIO16 (PWM) --> AOD4144 gate --> 12 V heater (low-side switch)

Storage split:
  microSD card ............... ALL sensor data logs (data*.log)
  Internal flash (LittleFS) .. ONLY the web page (index.template.html)

4. PERIPHERALS / HARDWARE
-------------------------------------------------------------------------------
a) CD74HC4067 16-channel analog multiplexer
   - 3.3 V supply, ~70 ohm on-resistance, EN tied active
   - Firmware waits 10 us after switching + 50 us settling before each read

b) PID Temp Sensor (channel C1) - controls the heater
   - 100 k NTC, Beta = 3950 K (same type as the Creality Ender 3)
   - R25 = 100,000 ohm; series resistor = 100 k part, measured 98,000 ohm
   - Wiring: 3.32V -- [98k] -- C1 -- [NTC] -- GND
   - Used by the PID and by the over-temp / sensor-fault safety checks
   - Resolution: ~4-6 ADC counts per C at 60-70 C

   AUX Temp Sensor (channel C2) - redundancy / sanity check
   - MF55 ultra-thin 10 k NTC, Beta = 3950 K (B25/50), +/-1 %, 0.7 mW/C
   - Series resistor = 2.0 k ohm, measured 2.00 k (sized for 60-70 C, where the
     NTC is ~2.5-1.8 k): ~9 ADC counts per C (~0.11 C per count)
   - Wiring: 3.3V -- [2.0k] -- C2 -- [MF55 NTC] -- GND
   - Logged and displayed only: NOT used by the PID or the safety checks
   - Self-heating with 2.0k: ~1.4 mW at 65 C, up to ~1.9 C high in still
     air (less when pressed against a surface; 2.7k reduces it ~25 %)

   Measurement circuit: the NodeMCU / D1 mini routes A0 through a 220k/100k
   divider to the ESP8266's 1.0 V ADC. So A0 full scale is 3.2 V, and A0 puts
   a 320 k load on whichever divider the mux selects. The rail is 3.32 V.

   Conversion for both (Beta equation, with the A0 load removed):
       V = ADC/1024 * 3.2 * gain        (gain = ADC_CALIBRATION_GAIN, 1.0 for now)
       P = Rs * V / (3.32 - V)          NTC in parallel with the 320 k load
       R = P * 320k / (320k - P)        NTC alone (Rs = 98k PID, 2.0k AUX)
       1/T = 1/298.15 + ln(R/R25)/3950  (R25 = 100k PID, 10k AUX)
       T(C) = T(K) - 273.15
   - Before this model: PID read ~5 C hot (its ~50 k divider is pulled ~14 %
     low by the load), AUX ~4 C cold (3.3 vs 3.2 V full scale). The 10 C gap
     at room temperature drops to ~0.01 C with the model.
   - Error value -999 if ADC <= 1 (short), ADC >= 1023 (saturated: AUX
     unplugged or < ~-11 C), or R > 20 x R25 (open: an unplugged PID NTC
     reads ~2.54 V because of the load, so it can't be detected by voltage)
   - Calibration (next step): ice bath at 0 C, fit ADC_CALIBRATION_GAIN.
     AUX has only ~3 counts/C near 0 C, so it is the most sensitive to gain.

c) Voltage channel (C0)
   - voltage = ADC / 1024 (0-1 V scale, 10-bit, ~1 mV per step)

d) microSD card module
   - SPI at 3.3 V, CS = D8/GPIO15, initialized with SD.begin(SS)
   - Card: FAT32 (or FAT16 for <= 2 GB). Class 10 or faster recommended
     (SD_WRITE_TIMEOUT_FIX.md: slow cards caused watchdog trips).
   - A Wemos D1 mini micro-SD shield uses the same pins.
   - [Fill in: card brand/size and module used on your board]

e) Heater driver: AOD4144 N-channel logic-level MOSFET
   - Low-side switch: +12 V -> heater -> drain; source -> GND
   - Gate driven directly from GPIO16 (3.3 V), 10 k pull-down keeps the
     heater off during boot/reset
   - Vgs(th) 2-3 V, so 3.3 V turns it on but not fully (Rds(on) is rated
     at 4.5 V). Optional TC4420 gate driver for high currents.
   - 12 V supply ground tied to ESP8266 ground; fuse the heater supply

f) WiFi radio (built in): access point for the web UI


5. SAMPLING / TIMING
-------------------------------------------------------------------------------
Parameter               Value       Meaning
----------------------  ----------  ---------------------------------------------
SAMPLE_INTERVAL         2 ms        One ADC read every 2 ms, cycling C0->C1->C2
Per-channel rate        ~167 Hz max Each channel read every 6 ms
CSV row rate            ~167 rows/s One row per C0+C1+C2 cycle (theoretical max);
                                    the three readings are within ~4 ms
Mux settle              10 + 50 us  Before each analogRead
BUFFER_SIZE (window)    50 rows     RAM buffer, written to SD when full
                                    (~every 300 ms at the full rate). Reduced
                                    from 100 to save ~1.4 KB of RAM.
WEB_UPDATE_INTERVAL     500 ms      Latest row pushed over WebSocket (2 Hz),
                                    slowed from 100 ms to save memory
PID_INTERVAL            500 ms      PID recomputed twice per second
DEBUG_INTERVAL          1000 ms     Serial status print
Low-heap guard          < 8000 B    Free heap below this auto-stops logging
                                    and flushes the buffer

Real rates are lower than the maximums: sampling pauses during each SD write
(open, size check, write 50 rows, close) and during the 1 s debug print
(~10 ms of mux reads). The older docs' "500 Hz per sensor / 1000 Hz total"
figure is not what the code does.


6. TEMPERATURE CONTROL (PWM + PID)
-------------------------------------------------------------------------------
PWM output:
  Pin ................. GPIO16 (D0) -> AOD4144 gate
  Frequency ........... 32 Hz (analogWriteFreq(32)), see section 9
  Resolution .......... analogWriteRange(1000) -> 0.1 % steps
  Mapping ............. duty % -> PWM value = duty/100 * 1000

Setpoint / limits:
  Default target temp ......... 45.0 C
  Settable range .............. 0 to 130 C  (GET /temp/set?temp=<value>)
  MAX_SAFE_TEMPERATURE ........ 130.0 C  -> emergency shutdown
  Sensor-fault window ......... < -50 C or > 200 C while heater is on -> shutdown
  MAX_HEATER_TIME ............. 1,800,000 ms = 30 min continuous heating -> shutdown
  Reset allowed below ......... 120 C (MAX_SAFE_TEMPERATURE - 10) and only
                                with a valid sensor reading

PID gains (defaults; comment in code: "tested and work well at 50 C"):
  Kp = 2.2      Ki = 0.25      Kd = 0.15
  Changeable at runtime: GET /pid/params?kp=&ki=&kd=  (resets the integral)

Algorithm (updatePIDController, every 500 ms, dt = 0.5 s):
  temp       = latest buffered PID Temp Sensor reading, or a direct read of
               that sensor if the buffer is empty (so the PID works with
               logging OFF). The AUX Temp Sensor is never used here.
  skip update if temp is invalid (< -50, > 200, NaN)
  error      = target - temp
  P          = Kp * error
  integral  += error * 0.5,   clamped to [-100, +100]
  I          = Ki * integral                     (max +/-25 % of output)
  D          = Kd * (error - last_error) / 0.5
  output     = P + I + D, clamped to 0..100 %
  heater PWM duty = output   (continuous, no on/off threshold)

How it behaves (for slides):
  - The PID now sets the heater power continuously (0-100 %) instead of
    switching a relay on/off, so the temperature is smoother.
  - The P term alone reaches 100 % when the error is above ~45 C, so a cold
    start heats at full power and then tapers off near the target.
  - The integral can contribute at most 25 %. If holding the target needs
    more than ~25 % power, the temperature settles slightly below the target
    by about (needed % - 25) / 2.2 degrees.
  - D acts on the error, so changing the setpoint causes a one-step kick.
  - The PID runs whether or not logging is on.

Manual control: /relay/on = 100 % PWM (disables PID); /relay/off = 0 %.
  (The route names are left over from the relay version.)

Safety layers:
  1. Ticker every 500 ms: heater on for more than 30 min straight -> PWM 0,
     shutdown
  2. Main loop: over-temp (> 130 C) and sensor fault -> shutdown
     (PID Temp Sensor only; the AUX Temp Sensor does not trigger shutdowns)
  3. Main loop: safety ticker hasn't run for 1.5 s -> shutdown
  4. Software watchdog ticker (8 s): loop stalled -> PWM 0, shutdown
     (8 s leaves room for slow SD writes)
  5. ESP8266 hardware watchdog as a backup
  6. SD writes limited to 5 s with frequent watchdog feeding
  Shutdown latches: PWM 0, PID off, logging off, open file closed.
  Recover with the "System Reset" button (GET /system/reset): no reboot
  needed, but it is refused if the temperature is >= 120 C or the sensor is
  invalid. It also clears the buffer so old readings can't re-trigger.


7. DATA SAVING (SD CARD)
-------------------------------------------------------------------------------
Medium ............... microSD card over SPI (FAT32/FAT16)
File names ........... data.log, data_1.log, data_2.log, ...
                       A NEW file is created at every boot (next free number)
File rotation ........ When the current file reaches 50 MB (MAX_FILE_SIZE =
                       50,000,000 B), a new data_N.log is started with a header
Header ............... timestamp,voltage,temperature,heater_state,target_temp,pid_output,
                       voltage_adc,thermistor_adc,thermistor_v,pid_enabled,kp,ki,kd,
                       aux_temp,aux_adc,aux_v
Write strategy ....... 50-row RAM buffer -> open file, append 50 rows, close.
                       Also flushed on Stop Logging and on low-heap auto-stop.
Write protection ..... 5 s max per write; watchdog fed every 5 rows; skips a
                       batch if a write is already in progress; warns about
                       slow cards (> 1 s open/close, > 2 s total)
Persistence .......... Data on the card survives power loss (except up to 50
                       rows still in RAM)

CSV columns:
+---+--------------+-------+------------+---------------------------------------+
| # | Column       | Unit  | Format     | Description                           |
+---+--------------+-------+------------+---------------------------------------+

Columns 1-6 are the original format; 7-16 were added after them.
thermistor_v and aux_v let you re-check every temperature:
  P = Rs * V / (3.32 - V);  R = P * 320k / (320k - P)
  1/T = 1/298.15 + ln(R/R25)/3950  (T in K)
  PID: Rs = 98k, R25 = 100k     AUX: Rs = 2.0k, R25 = 10k
  -> matches the logged temperatures to within a few thousandths of a C.
  (Logs from before the circuit model used V = adc/1024 * 3.3 and
   R = 100k * V / (3.3 - V); recalculate them from the raw *_adc columns.)

9. THINGS TO KNOW BEFORE PRESENTING
-------------------------------------------------------------------------------
1. BOOT FILENAME FIX (committed):
   - "Download Data" with no file name now downloads the current log file
     (flushing the buffer first) instead of failing with "400 Missing file
     parameter".
   - If the SD card wasn't ready at boot, Start Logging retries the SD setup
     and refuses (HTTP 503, message shown on the page) if it still can't
     create a log file, instead of logging into nothing.
   - README, WIRING_GUIDE, config.h and the other docs now match the code.
2. PWM frequency: 32 Hz. The ESP8266 core docs list 100 Hz as the
   analogWriteFreq() minimum, but in core 3.1.2 (what PlatformIO's
   espressif8266 platform uses) the default PWM engine takes the requested
   32 Hz directly. Only its fallback path clamps to 100 Hz. A scope should
   show a ~31 ms period.
3. Over-temperature check gap: the over-temp and sensor-fault checks use the
   logging buffer. With logging OFF the buffer is empty and those checks are
   skipped, even though the PID can still heat. Only the 30 min runtime limit
   and the watchdog apply then. Keep logging on whenever the heater runs, or
   make the safety check read the sensor directly.
4. 30-minute limit: under PID the duty rarely drops to 0 %, so a long hold
   counts as "continuous heating" and triggers a shutdown at 30 min.
5. ADC scaling: on a NodeMCU/D1 mini, A0's onboard 220k/100k divider gives a
   3.2 V full scale and a 320 k load. The thermistor conversions now model
   both (see section 4b). The voltage channel still uses ADC/1024 (0-1 V), so
   the logged "voltage" is the real voltage / 3.2 on those boards.
   Still to do: ice bath calibration (ADC_CALIBRATION_GAIN), then re-test at
   45 C. Note that the corrected PID reading is ~2 C lower than before at
   45 C, so the same setpoint now holds the part ~2 C hotter than before
   (it was actually sitting ~43 C).
6. If the SD card isn't ready at boot, no log file is created. Insert the
   card and press Start Logging (it retries), or reboot.
7. Boot pins: D3/D4 must be HIGH and D8 LOW at power-up. Most SD modules
   are fine on D8, but check if the board won't boot.
8. On the ESP8266 the hardware watchdog timeout can't really be set, so the
   10 s value passed to ESP.wdtEnable() is likely ignored. The software
   watchdog ticker (8 s) is the one that matters.
